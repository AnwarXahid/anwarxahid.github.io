# Portfolio migration and rollback

Inspected baseline: clean `master`, origin `https://github.com/AnwarXahid/anwarxahid.github.io.git`, Jekyll layouts/front matter, no checked-in GitHub Actions workflow or CNAME. The remote repository's live Pages configuration is an external account setting; it has not been modified or assumed verified. Work is on `feature/astro-quizora`.

The exact existing content remains in `_pages`, `_posts`, `_publications`, `_portfolio`, `_data`, `_layouts` and `_includes`. Astro renders these at build time through `src/lib/portfolio.ts`. Existing CSS, JS, fonts, images, PDFs and talkmap files are copied byte-for-byte to the same output paths by `scripts/assets.mjs`. No Ruby/Jekyll runtime is required to build the new site. No portfolio React root is added. The only new portfolio navigation entry is Quizora, injected into the build-time navigation data.

`docs/migration-inventory.json`, generated by `npm run inventory`, lists original paths, redirects, titles and SHA-256 asset hashes. It includes:

- `/`, `/about-me/`, `/blog/`, `/works/`, `/publications/`, `/fun/`, `/404.html`.
- Three blog posts under `/blog/<original-slug>/`, including original capitalization.
- Four existing publication paths and all project collection paths.
- Static redirects from `/about/`, `/about.html` and `/resume` to their existing destinations.
- `/files/resume.pdf`, three paper PDFs, all images/fonts/scripts/styles, the talkmap directory and `robots.txt`.
- RSS at `/feed.xml` and a static sitemap, canonical URLs, OpenGraph, Twitter metadata, Person and publication structured data from existing layouts.

The blog and collection pages retain original claims and citations. No publications, biography facts or credentials have been invented. The old comments data remains in the repository, but the active baseline layouts do not render a comment submission form; the migration does not introduce one. Legacy helper scripts and unused theme sources remain available for rollback.

The `/fun/` HTML, dedicated layout, CSS and JS are unchanged. This preserves Bug Panic sprint/Zen/keyboard controls, daily Ph.D. fortune and Reviewer #2 behavior. Browser checks exercise the actual controls, not merely an HTTP status. Asset checks compare output bytes with the inventory. The new `/exam/qr/` tool is part of the Astro build and does not change old portfolio URLs.

## Rollback

Before adopting Actions deployment, retain the baseline commit and record the current Pages source setting. Since old Jekyll inputs remain, rollback can restore the old package/configuration/deployment choice or redeploy the baseline commit and return Pages to its original branch source. A frontend rollback does not restore/delete Cloudflare data and should not be coupled to a D1 rollback. Do not discard exam data as part of reverting the portfolio.

Astro uses a Liquid compatibility layer intentionally to avoid a large simultaneous content rewrite. A future gradual conversion to native Astro/content-collection templates can retain the same inventory checks and original data. This compatibility layer is build-only and receives only trusted repository content, never learner or imported document input.
